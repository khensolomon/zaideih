# Architecture

Zaideih is a static, offline-first HTML5 app. One shared codebase (`src/`) runs in two shells: the web (an installable PWA served by any static host) and the desktop (Electron). There is no application server: the catalog ships as JSON, the browser keeps the user's library, and a Cloudflare Worker streams audio from R2.

```
assets/data/*.json ──tools/catalog.mjs──▶ build/catalog/catalog.<hash>.json + meta.json
                                                   │
                          tools/build.mjs --platform web|desktop
                                                   ▼
                  dist/web (PWA)          platforms/desktop/app (Electron renderer)
                        │                               │
                        └──── GET /audio/:id ───────────┘
                                     ▼
                     worker/media (D1: id → path) ──▶ R2: music/{folder}/{file}
```

## Data

| File | Role |
|------|------|
| `albums.json` | Albums and tracks. Track `i` is the global track id used everywhere (likes, playlists, downloads, audio URLs). |
| `artist.name.json` | Artist names, `aka`, spelling variants (`thesaurus`) and type. |
| `category.json` | Language, genre, artist-type and album-type tables. |
| `media.json` | Audio object path for every track: `[albumUid, folderPath, [[trackId, fileName], ...]]`, one album per line. |
| `album.name.json`, `track.name.json` | Tag corrections used at ingest time. The app does not read them. |

`tools/catalog.mjs` validates every reference and fails, listing every problem, when anything is inconsistent: an unknown artist, genre or language id, a duplicate track id, or a track without an audio path in `media.json`. Text is normalized to NFC; the source tags contain Myanmar marks in non-canonical order (U+103A before U+1037), which breaks word segmentation and search. The output is one content-hashed catalog file (about 1.8 MiB, 0.5 MiB compressed) plus a small `meta.json` that names it.

`media.json` was generated from the last Django database dump with `node tools/media.mjs import <dump.sql.gz> --apply`. The importer reads only the `album` and `track` tables; dumps also contain user and session tables and are never committed (`*.sql.gz` is ignored).

## App

- Vanilla ES modules, bundled and minified by esbuild. Hash routing (`#/album/…`) works on any host without rewrite rules.
- `src/app.js` exports `boot(platform)`. Each platform entry (`platforms/web/main.js`, `platforms/desktop/renderer.js`) passes its name and catalog location; the web entry also registers the service worker.
- The whole catalog is held in memory. Search normalizes text (NFKC, zero-width characters removed, Latin diacritics folded, Myanmar marks kept) and also matches artist `aka` and spelling variants, with and without spaces.
- Myanmar text is split into words with `Intl.Segmenter` (syllables where unavailable) and wrapped in non-breaking spans, because Chromium otherwise breaks lines inside syllables.
- Artwork is generated from catalog data, since the data has no images (`src/ui/art.js`). Every choice is deterministic, so an album or artist looks the same everywhere.
  - Album cover: grey shade from the album id; a faint texture from the genre (rings for gospel, hymn and worship; weave for tribal, folk, ethnic and classical; grooves otherwise); the language code, year and title; and a strip with one bar per song, height from its length and brightness from its plays. The playing song's bar is lit.
  - Album motif (`albumShape`, `albumMotif`), in the upper right: who sings the album, read from the song credits. Solo: a record, one ring with a band per song inside (width from the song's length, brighter when more played). Duet (most songs credited to two artists together, or two artists sharing the album): two overlapping rings with the overlap lit. Various (many artists, none with half the songs, or the Various Artists credit): a ring of dots, one per artist (up to 12), sized by their songs. Single (3 songs or fewer): a record with a large label. Ring lines follow the artist type as on artist pictures (plain male, a bead for female, dotted for groups, hairline unknown); the motif's size follows the album's length (up to an hour) and its placement varies slightly per album. Popularity: faint echo rings around it, one more per half order of magnitude of plays from 100 (up to five), and albums with 10,000 plays or more draw it in the accent colour. The lock-screen image draws the same motif.
  - Artist picture: one ray per year from the first to the last release, clockwise from the top, with length from that year's songs and brightness from its plays (the most played year uses the accent). The centre grows with total plays; faint rings count albums (one more ring each time the count doubles, up to six); ray ends show the artist type (plain for male, a dot for female, dotted for groups or various artists, outline when unknown). Latin names show up to two initials in the centre. Myanmar names show none, since a single letter of a Burmese name does not read as the name.
  - Lock screen, media keys, CarPlay and car stereos: the playing song as a picture (`src/ui/now-art.js`), since many car stereos and older accessories cannot show Myanmar text and some nothing beyond Latin: the album's shade, pattern and motif above; below, the song's title as large as fits in two lines, up to four of its artists and how many more (Unknown and Various left out; the album's when the song names nobody), the album with its year, and the album's songs as a strip with this one lit. Drawn with the app's own fonts (Outfit, Padauk, loaded once with the page in front; a picture drawn before they arrive is drawn again), as a JPEG data URL. It is drawn at once, without waiting: the motif is painted on the canvas from albumMotif's own circles, not decoded as an image, so a song changed from the car with the page in the background gets its picture in the same moment, with its title, artists and album. The songs around the playing one (one back, three ahead) are drawn ahead too. Tapping the song on the iOS lock screen opens the web app iOS associates with the session: WebKit bug 267810 has it open another installed web app; the manifest's explicit `id` is the known remedy, and an install made before it may need adding again.
- Logo: the mark from `assets/psd/icon.svg` (`src/ui/logo.js`), shown on a `#5a5a5a` tile. The app icons in `platforms/web/public/icons/` are generated from the same path.
- Status bar: installed on iOS the app runs under a transparent status bar (`apple-mobile-web-app-status-bar-style: black-translucent`, with `viewport-fit=cover`); the page fades and blurs under it and behind the floating controls, like the system's scroll edge, and Now playing scrolls under a darker blur. `theme-color` (Safari's bar, Android's status bar) follows the page and switches to Now playing's colour while it is open. iOS reads the status-bar setting when the app is added to the Home Screen, so an existing install may need to be added again.
- The player bar on wide windows (`src/ui/bar-extras.js`): from 1280px it adds Lyrics (the playing song's page), Sound and the Sleep timer beside the volume; from 1600px Up next, the next song in the queue, a tap playing it now (the next three from 2300px); from 1900px the line being sung beside the song, for songs with timed lyrics. All but the line are drawn always and shown by width; the line's lyrics are read only while the window is wide enough to show it.
- Wide screens: the pages of covers and cards (home, a language, genres, search, the songbooks) take the whole width beside the sidebar, and their tiles grow with it (`--tile`, `--tile-row`, `--person`, `--book`, from the room beside the sidebar, between a least and a most size), so a large screen shows larger covers and a few more in a row rather than many small ones; gaps and side margins grow too. Their lists of songs fall into two or three columns from 1900px. Pages read top to bottom (an album, an artist, lyrics, a list of songs, text) keep a reading width (1120px, 1280px from 1700px).
- Navigation: wide screens use the sidebar. Its toggle collapses it to icons (languages as two-letter tiles), each with its name as a hint, and its Languages and Browse sections fold under their headings, as does "About Zaideih" at its foot (About, Help, Terms, Privacy), folded until opened; all are kept per device (`localStorage`, `zaideih.rail`). Small screens use iOS-style floating controls instead of a bar, each its own "liquid glass" piece (translucent, blurred, light edge): a round icon-only Back (when not on Home) and a round logo button on the left, Search and Library sharing one pill on the right, and the page title between them as plain text, over a fade of the page. The logo opens a menu with everything the sidebar holds (places, languages, browse, About, Terms, Help); while it is open the page behind it is blurred and held still (pinned at its scroll offset, since iOS scrolls a page even with `overflow: hidden`), and any link in it closes it, including one to the page already open. Page titles are iOS large titles: the bar shows the title only once the page's own heading has scrolled under it (IntersectionObserver). The controls are fixed rather than sticky, so when the page is pulled past its top or bottom (the iOS rubber band) they stay where they are and only the page moves; the side columns never get narrower than their round buttons, so a long title is cut short instead. While the keyboard is open they follow the visible area (`--vvt`, the visual viewport's offset). On the search page the search bar takes their place, fixed at the top in the same way, with Back on its left and Clear on its right when there is text (see Search page). Its suggestions open as one glass panel as wide as the whole bar (field and button), with the scope buttons sharing its width, and end where the on-screen keyboard begins (`--vvh`, from `visualViewport`). Back follows in-app history (depth kept in `history.state`) and goes Home when there is none, e.g. after opening a shared link. `body[data-page]` names the page kind for such layout rules. In the app on the home screen, iOS 26 lays out fixed elements against a viewport shorter than the screen by the status bar while the page is shorter than the screen (WebKit bug 301108), which floated the player above the bottom edge on short pages and while the menu was open; the document is therefore never shorter than the screen there (`html { min-height: min(100lvh, calc(100% + env(safe-area-inset-top))) }`, `display-mode: standalone` only).
- Installed on a desktop (Chrome, Edge), the app draws its own title bar: the manifest asks for `display_override: ["window-controls-overlay"]`, so the system strip is gone and only the window's buttons stay, over the corner `env(titlebar-area-*)` names (`--tb-sys` their height, `--tb-end` their width at the right edge). A bar along the top of the page (`.topbar`, right of the sidebar), at the system title bar's own height so the window's buttons sit in its middle (`--tb-h`, at least 30 px; its controls `--tb-ctl`, 6 px less), holds Back, Forward and a search field, and the sidebar's logo and toggle sit in the same strip; its empty parts and the sidebar's head move the window (`app-region: drag`), and double-clicking them maximises it. Search is always there, so the sidebar's Search link is hidden; on the search page its own field takes the bar's place, its scope buttons shown as icons only, and open suggestions blur the page below the bar only, so the bar, the sidebar's head and the window's buttons stay one sharp strip. The lyrics studio and the Workspace put their own header there instead (`body[data-studio]:has(.st-head)`), at the bar's height, with their controls sized to it. Once the page has scrolled, the bar (or that header) casts a soft shadow over the content under it (`body[data-scrolled]`). On macOS the buttons are on the left, over the sidebar, which then starts below them (`body[data-tb-left]`, set from `navigator.windowControlsOverlay`, `geometrychange`). A narrow window keeps the floating controls, under a strip to move it by; Now playing starts below the buttons and its empty space moves the window. The small arrow Chrome puts in the bar switches back to the system title bar, and then, as in a browser tab, on phones, Safari and Firefox, none of this applies. The overlay counts as an installed app wherever `display-mode: standalone` is checked (sign-in, scroll bars). Installed on a desktop, with either title bar, the sidebar's head fades from the title bar's colour (the page's, `theme-color`) into its own darker one, its edge fading in with it, so no seam shows where they meet.
- App feel on phones: a loading screen (logo and a running bar, in `index.html` with the page colour inline, so an installed app never shows a white page while the scripts and catalog load) that fades after the first page is drawn; no scroll bar on touch screens and in installed apps (scrolling unchanged); body text at 17 px; controls and list items cannot be text-selected or long-pressed into a link preview; taps do not flash; double tap does not zoom, while pinch zoom stays for those who need it (iOS ignores requests to disable it anyway).
- Library (`#/library`): Liked songs first, as a large card with Play; then playlists (cards, New); then rows for Downloads, Recently played and Uploads (signed in, or an invitation to sign in); then the backup. Each section is its own page, `#/library/<section>`, with "Library" above its title.
- Home starts with recently played songs and the most played artists per language (up to 12, from catalog play counts; the catch-all credits "Unknown" and "Various Artists" are excluded).
- Album tiles show the title, the main artist (with "+N" for the rest), year, song count and a mark when every song is downloaded. On pointer devices a play button appears over the cover on hover or focus and plays the album without opening it.
- Search page: where to look as chips with an icon each and how many were found (All, Artists, Albums, Songs, Lyrics; Lyrics lists the songs with a line of the words). Before anything is typed: the recent searches (each can be forgotten, or all), questions to try, and the languages. On phones the search takes the bar's place as one glass bar: Back on its left (where the bar's Back is, away from Library), the field, and Clear on its right when there is text; the chips stay under it while the results scroll, named only when chosen. Back and Clear keep the keyboard until the tap has landed, and the bar that comes back takes no taps for a moment, so one tap never lands on two buttons. Dragging the page while the field has the keyboard closes the keyboard, as native apps do (the field, its buttons and the suggestions list scroll as they are): with the keyboard open iPhone pans the page under the fixed field, which follows only once Safari reports the pan, so the field seemed to scroll with the page. While a text field has the focus on a touch screen (`body[data-typing]`) the player and its fade step aside, everywhere but the lyrics studio, which keeps the player above the keyboard to play while writing.
- Search suggestions (`src/ui/suggest.js`, an ARIA combobox): typing shows up to 3 artists, 3 albums and 5 songs; picking a song plays it. The empty box lists recent searches, kept per device in `localStorage` (`zaideih.recent-searches`). While the list is open, the box and the list form one panel and the page behind is dimmed and blurred.
- Close matches (`closest()` in `src/core/search.js`): when fewer than 4 records match exactly, artists, albums and songs within a few typos (1 for up to 4 characters, 2 up to 8, 3 beyond) fill the list. A record is compared three ways and the best wins: its whole name or title without spaces, the start of it (for a query typed part way), and word by word. A character-set check skips records that cannot be close, which keeps a pass over the full catalog to tens of milliseconds.
- Scopes: All, Artists, Albums, Songs or Lyrics, as chips with icons, kept in the address as `in=`. Within Albums or Songs, records by a matching artist follow the title matches, since people often type the artist when they want an album. Typing an artist's name in All offers "Albums by …" and "Most played songs by …".
- My music: signed in with uploads, the scope chips end with My music (a lock), on unless turned off on the device (`zaideih.search.mine`). With it on, the person's own songs and albums are searched with the catalog, by their titles and their artists' names, since uploads have no artist pages (`withMine` in `src/core/search.js`, over `catalog.extra`) and marked with a lock in the results; nothing leaves the device.
- Questions (`src/core/intent.js`): `parseIntent()` reads a query as a question from a small vocabulary (order: most played, top, newest, oldest; kind: artists, albums, songs; years and decades such as "1987" or "90s"; "by <artist>" or "<artist> albums") plus the catalog's language and genre names. An order word alone with other words left over ("best friend", "new life") stays a title search. `answer()` lists the matching records and `describe()` titles them ("Most played Mizo gospel albums from the 1990s"). The answer leads the suggestions and the results page; a scope other than All decides what kind of record it lists.
- "Did you mean" (`didYouMean()`): the strict correction of an artist name or album title (`correction()`, up to 2 typos), otherwise the closest artist, album or song. It is offered when nothing matches and when only a few results do; a search with no exact matches lists the close matches.

## About and terms

`#/about` carries the slogan "Zaideih Music Station", the purpose (preserving the music, free to listen, nothing sold, no financial benefit), catalog figures, and the app version and catalog id; it is the only place the version is shown. `#/terms` covers listening, ownership, downloads, data, availability, rights holders and changes. Both link to the repository's issue tracker for rights holders. The sidebar foot and the Library pages link to both.

## Theme and player

- One theme, "graphite", with no light or dark variant and no switch. The page is the logo grey `#5a5a5a` with white text; the sidebar (`#525252`), cards and inputs (`#4e4e4e`), hover and selection (`#646464`), the player (`#3e3e3e`) and the covers are steps of the same grey.
- The accent is the logo's silver `#ececec`: the play button, progress, the liked heart, the playing song and the selected navigation item. It carries dark text (`#3a3a3a`, 9.6:1) and reads 5.8:1 on the page. The only other colour is a muted red for errors.
- Fonts: Outfit (Latin) and Padauk (Myanmar), both bundled for offline use under the SIL Open Font License (`platforms/web/public/licenses/`).
- Player: a floating card on every screen size, translucent over a blurred view of the page, with a vertical gradient, a brighter top edge and a shadow on all sides; a fixed strip fades and blurs the page where it passes under it. Seek bars are 8px tall with a 16px thumb and show how much of the song has loaded. Left and Right seek 5 seconds; Shift+Left and Shift+Right change song. The volume and mute are kept per device (`localStorage`, `zaideih.volume`); the queue, its position and shuffle and repeat are kept in IndexedDB (`kv`, `player`) and come back at the next start.
- Live animation (`src/core/visualizer.js`, `src/ui/viz.js`): the `<audio>` element is routed through Web Audio on its first play (the graph of the sound features, see Sound features) and read with an `AnalyserNode`. Frequency bars radiate from the play button and `--level` (loudness) drives its glow. In Now playing the bars sit on the progress bar and are lit over the played part. The draw loop runs only while playing and visible, and not at all with `prefers-reduced-motion`. Pausing freezes the bars and the glow in place (dimmed); they are redrawn on resize and copied into the Now playing view if it opens while paused.
- Getting around from what plays: the player's **More** (⋯) gives Now playing, the lyrics, the album, each artist, a playlist, the queue, Share and the sleep timer; in Now playing the artists are links and Lyrics sits beside the title. The playing song's row shows three bars in place of its number, moving while it plays. A song's lyrics mark in a list opens its lyrics.
- While nothing plays, the player's Play plays what the page is about (the page's own Play, marked `data-page-play`: an album, an artist's popular songs, a playlist, liked songs, downloads, Most played, a lyrics page's song), and says so ("Play Agape No.1").
- Sleep timer (`player.setSleep`, Now playing's moon and the player's More): playback fades out over 6 seconds and pauses after 15, 30, 45 or 60 minutes, or stops when the song playing ends. Not kept across visits; the fade does not change the saved volume.
- Artist page: a header with the years, songs, albums (and how many of others they appear on), plays and how many they sing with as labelled numbers (three a row on phones); under the buttons, their years as a strip (`careerHtml`): a bar a year as tall as its songs, the most played year lit and named under its bar (or at an end when it is near one), a dot under the years of their own albums, each bar naming its year, songs and plays; nothing for a single year. Then Play popular, Shuffle all and Radio (on phones Shuffle and Radio as icons), then Popular; **Sings with**, those they share songs with, most songs together first, each with how many; **With others**, those songs (duets, features); **Albums**, their own (they sing at least half of it, or are its first credit), apart from **Appears on** (compilations, others' albums); and **Similar artists**, in one of their languages, scored by albums shared, genres in common, years active overlapping and a little for plays, each saying what they share. **Radio** is two of their most played songs, shuffled, to one by those around them (the first six they sing with and six similar), held albums left out. All from the catalog on the device (`src/core/artist-links.js`); Unknown and Various Artists are credits, never someone sung with. On phones the two rows of artists are one row each, to swipe.
- Share (song menu, album menu, artist page, lyrics page, player's More): the device's share sheet where there is one, otherwise the link copied. A song is shared as its album with `?song=<id>`, which brings the song's row into view, lit for a moment.
- A song that cannot play says so once: in Now playing when it is open, otherwise in a notice with Help and its code.
- Search lists songs with their album covers in place of numbers.
- Progress bars show the time under the pointer on hover (pointer devices only).
- Analysis requires CORS: the element uses `crossOrigin = "anonymous"`, so streaming from an origin outside the Worker's `ALLOWED_ORIGINS` fails instead of playing silently through a muted graph. Blob playback of downloads is same-origin and unaffected.
- iOS and iPadOS: analysis is disabled, because Web Audio is suspended when the screen locks or the app is backgrounded, which would stop playback. The bars stay still; playback works normally.
- Now playing scenes (`src/ui/scenes.js`): full-screen WebGL backgrounds behind the Now playing sheet, fed each frame with 64 band energies from the analyser, reduced to bass, mids, highs, loudness and a beat pulse (bass jumping 1.3 times above its running average, at most one per 0.28 s). Five scenes: Halo, Aurora, Horizon, Warp and Weave. Each song seeds its own variation (shapes, speeds and a faint tint near the silver accent); Auto picks the scene from the album's cover pattern. The choice (Auto, a scene, or Off) is kept per device in `localStorage` (`zaideih.scene`). Time runs faster in loud passages, so long listening keeps changing. Watch shows the scene full screen (fullscreen where allowed) with a light layer of its own: the song, album and year, progress, previous, play and next, the next background, "Keep song info" (the title and artist stay as a caption, kept per device in `localStorage`, `zaideih.watch.info`), and leaving (also Escape). The layer fades after 3.5 seconds while playing, stays while paused or while a control is in use, and comes back on pointer movement, a key, or a tap or click; a click on the empty scene while it shows hides it. The loop runs only while the sheet is open and the page visible; resolution starts at about 1.25 device pixels and drops when frames run long. Without analysis (iOS, iPadOS, paused) scenes breathe slowly on their own; with `prefers-reduced-motion` one still frame is drawn; without WebGL (graphics acceleration off, or the GPU blocked by the browser: Chrome no longer falls back to software WebGL) the sheet stays plain without a notice, and the background button explains it: the reason the browser gives, and numbered steps to turn acceleration on for that browser (Chrome, Edge, Opera, Firefox, Safari; `enableSteps`). A scene whose shader does not build on a device is marked unsupported in the picker, and Auto uses another. A lost graphics context (GPU reset) is restored by the browser and the scene resumes. Shaders use high precision where the device offers it.
- Over a scene, the Now playing cover and the queue are see-through (translucent grey with a light blur) so the animation shows behind them.
- Desktop Now playing scrolls as one page: the cover and controls stay in place (`position: sticky`) while the queue scrolls.
- Hints (`src/ui/tips.js`): icon-only buttons and links show their accessible name in a bubble on hover, on keyboard focus, and on a long press on touch screens (the long press then does not activate the control).

## Album holds

Albums can be held back from listeners without a release: streaming off (listed, greyed out, not playable) or hidden from the public, set in the Workspace by the Albums right and enforced by the audio Worker. The app reads them at start and every 5 minutes (`src/core/holds.js`). See [holds.md](holds.md).

## Workspace

The Workspace, `#/workspace`, edits the catalog through GitHub: `assets/data` in git stays the source of truth, and every edit is a reviewed, released commit. It is its own bundle (`src/workspace`, `assets/workspace.<hash>.js`), loaded only when the page opens, so listeners never download it; web only. Its link appears for those signed in with GitHub. Until 26.10.25.6 it was the admin page: `#/admin` addresses (in older pull requests, bookmarks and sign-ins from older app builds) forward to `#/workspace`, and keys kept under `zaideih.admin.` move once to `zaideih.workspace.` (`src/core/moved-keys.js`).

- Connect: Sign in with GitHub (the GitHub App "Zaideih", finished by the audio Worker's `/auth` routes, see [worker-audio.md](worker-audio.md#sign-in-with-github); `src/workspace/session.js`, kept in `localStorage` as `zaideih.workspace.session` and renewed before its 8 hours run out; while GitHub is open, the sign-in's verifier and nonce wait in `sessionStorage`, `zaideih.workspace.signin`), or a fine-grained GitHub token for `khensolomon/zaideih` only (Contents and Pull requests read and write, Checks read), kept as `zaideih.workspace.token`. The person's level comes from their repository permission (`src/core/access.js`): admin (admin or maintain), editor (write), contributor (triage), guest (any other GitHub account), viewer (not signed in). Editors and admins publish; contributors and guests signed in with GitHub send their draft as a suggestion, a pull request the audio Worker opens for them ([worker-audio.md](worker-audio.md#suggestions)), which editors see listed from the admin Overview and review on GitHub. A token without write access is refused. The level is kept on the device (`zaideih.workspace.who`) only while the sign-in or token behind it lasts; every page uses it to show "Admin" or "Suggest edits" in the sidebar and the logo menu, and About offers listeners the sign-in. The level only shapes the interface: GitHub decides what each request may do. While Google Analytics is on for the device it refuses to start and never reads the token, since a third-party script on the page could read it. The CSP allows `https://api.github.com` for this.
- Catalog: find an album (title or id) or an artist (Ctrl+K or ⌘K from anywhere on the page); an album's page changes its title, year, language and genres, its songs' titles and artists (by name, from the catalog's artists), hides or shows songs, and plays a song in the app's own player; an artist's page changes the name, other name, type and search spellings and lists the albums. Each field goes to the draft as soon as it changes (on leaving it, or at once for switches and lists) and stays marked until the draft is published. Values are checked and NFC-normalized first (`cleanValue`); a refused value is named, stays in the field to be corrected, and the draft keeps what it had.
- Draft (`src/workspace/draft.js`): changes are kept as a list of `{kind, id, field, value}`, not as edited files (`zaideih.workspace.draft`), shown one line each with Undo. At publish time the newest files are read from master and the changes applied to them, so an edit made on GitHub meanwhile is not overwritten; a change whose record is gone stops the publish and is named.
- Publish: one commit on a new branch (`catalog-edit-<version>-…`; a flat name, since `admin/…` cannot be created while a branch named `admin` exists) with the changed data files (written in the repository's format, so only the changed lines differ) and the release files for the next version (`releaseFiles` in `tools/lib/version.mjs`, shared with `tools/version.mjs`): both `package.json` files, both lock files and a changelog section from the note. Then a pull request into master, whose checks the page follows. "Merge and release" is enabled when they pass; it squash-merges with `release: web <version> <note>` as the first line, so the release workflow builds and deploys it, and deletes the branch.
- Hidden songs: `h: true` on the track in `albums.json`. The catalog build leaves them out (and an album whose songs are all hidden), keeping their ids, so likes and playlists simply no longer list them; showing a song again brings it back.
- Statistics: the counted plays from `GET /plays`, in total and for the last 30 days, with the top 25 songs of each.
- Checks (`src/workspace/health.js`): checks of the source data, each listing what needs a look (up to 200 items, each opening its editor): titles and names with stray spaces or a non-NFC form (with one button that adds every correction to the draft), songs without an artist or a length, albums without a year or a genre, artists who may be listed twice (the same name ignoring case, accents and spaces, both with songs), hidden songs and artists without songs.
- Layout: before connecting, one sign-in card in the middle of the page (Sign in with GitHub, or a token). Connected, a page of its own like the lyrics studio (the sidebar narrows to icons, the floating bar is hidden, the app's player stays): one header with the lyrics studio's height and parts, Back (an album or artist back to the results, a section back to Overview; from Overview back to the app, on phones only, as wide screens have the sidebar), the section and a line under it (the person's level and what they have had released: merged catalog edits, or accepted suggestions, from GitHub's search; nothing shown when that is unavailable), the find field (on wide screens a real field, results in Catalog as it is typed, the Catalog page's own hidden; narrower, an icon to the page's field), the sections as icons with hints (Overview, Requests, Lyrics, Members, Checks, Statistics; a dot where something waits; Catalog has no icon, the find field being the way into it), the Draft button with its count, and the person's GitHub photo, which opens their menu (load the newest catalog, sign out). On phones the sections take a row of their own. Overview gathers what waits for the person (requests, lyrics proposals and reports, suggestions, data checks), the draft, the latest lyrics edits and the plays of the last 30 days. While editing, a bar above the player shows the draft with Undo last and the way to publish it.
- Edit from any page: for someone signed in, album and artist pages show Edit (editors) or Suggest an edit (contributors, guests), and a song's menu Edit song details or Suggest a correction. They open `#/workspace?album=<id>[&track=<id>]` or `#/workspace?artist=<id>`, which opens that editor (and highlights and focuses the song) once the catalog is loaded, then clears the address. Listeners see none of it.
- Requests (`src/workspace/publish.js`, for Review publishing): members' albums asked to be published, the waiting ones listed beside the one being reviewed (Waiting and Decided); each song plays on the page, pausing the app's player while it does; the title, year, language, genres and each song's title and artists are set there; approving builds the new album, songs, artists and `media.json` row from the newest files, has the audio Worker copy the songs into `music/`, and opens a `release: web+d1` pull request ([library.md](library.md#asking-to-publish)); the request stays open with its pull request and Merge and release. Declining asks for a reason, which the member sees. `#/workspace?review=<id>` opens one's approval form; the owner's "Public in the catalog" switch on their own album goes there.
- Not yet: adding an album that is not in anyone's library.

## Accounts

A Zaideih account is one person, however they sign in (Google, GitHub or a passkey, on Your account, `#/account`): D1 `members`, with `member_logins` for their sign-ins (joined by verified email, or added while signed in) and `member_sessions` for Zaideih's own session tokens, which the Worker's own routes accept instead of GitHub tokens (`worker/media/accounts.js`, `src/core/account.js`). Catalog editing still runs on the person's GitHub sign-in. Design: [accounts.md](accounts.md).

## Personal libraries

Signed-in people keep their own music: uploads to the audio Worker (R2 `users/…`, D1 `members` and `uploads`), played through signed addresses, outside the public catalog, with rights the owner gives per member (co-owner, review publishing, moderate members, storage) and moderation, and music already in R2, wherever it is kept, added without moving or copying it; a member can ask for an album of theirs to be published in the catalog, reviewed like any catalog change. Design, limits and costs: [library.md](library.md). In the app, uploads join `catalog.extra` (`src/core/uploads.js`): found by id (`catalog.track(id)`, `catalog.album(id)`; text ids `u<id>`, `u-album-<n>`) so the player, album page, queue, likes and downloads work as for catalog songs, while catalog lists, search, counts and play totals never include them; they are never counted as plays or sent to analytics. Library has an Uploads page (`#/library/uploads`, `src/ui/uploads-view.js`); files are read in the browser (length from the audio element, tags from `src/core/tags.js`) and checked by the same rules as the Worker (`src/core/upload-rules.js`) before anything is sent.

## Sound features

Old recordings, many from cassettes, are improved live while they play (`src/core/sound.js`); the audio files are never changed. All of it runs in Web Audio on computers and Android. On iPhone and iPad it is off, because iOS suspends Web Audio when the screen locks, which would stop playback; the Sound panel says so.

Signal path: `<audio>` → one-sided fix (channel splitter, four gains, merger) → rumble cut (high-pass) → hiss shelf (high shelf at 7.5 kHz) → denoise (audio worklet) → headroom (gain) → ten equaliser bands → level (gain) → limiter (compressor) → mute → analyser → speakers. A side branch (high-pass at 100 Hz, so rumble and air thumps do not count) feeds the meter, a worklet that reports each channel's level every 50 ms on the audio thread, so decisions keep working in a background tab. The animations read the analyser at the end of the chain, so they show what is heard.

- Skip silence (`createSilenceSkipper`): a song started from the beginning is measured for half a second. If that is quiet (median below -38 dBFS), it plays muted at 8x until the level stays 10 dB above that quiet level for three readings (a click or a thump is shorter), then steps back to about half a second before the music began and fades in once that step back has happened (unmuting before it let the music's first beat through for a moment, heard as a kick at the start of every song). Between songs the sound is silent until the next one starts, at that song's remembered volume. Without music within two minutes it plays on as it is. Near the end (under 45 s left, after 30 s and at least 5 s of music), 2.5 s back at the tape's noise level ends the song as if it had played out, so repeat and the queue behave as usual. Where the music starts is remembered per song (`localStorage`, `zaideih.sound.tracks`, newest 3,000), and the next play starts there. A listener's own seek ends the start skip. Fast passages do not count as listening for play counts.
- Clean up: Off, Light (rumble cut at 75 Hz, -4 dB hiss shelf, denoise at half strength) or Strong (90 Hz, -3 dB, full strength). The denoiser (`src/core/sound-worklet.js`) is a short-time Fourier transform (1024 samples, 75 % overlap, Hann windows) with per-frequency noise tracked as the slowly rising minimum of the smoothed power, so it learns each recording's hiss from its quiet moments; gains have a floor (-14 dB at Strong), are averaged over neighbouring frequencies, open fast and close slowly, which limits the "watery" artefacts of strong noise reduction. It adds 23 ms of delay, the same at every setting. Tests: unchanged output at 0; on white noise with a tone, hiss more than 6 dB lower at Strong with the tone's level kept.
- Even out volume (`createLeveler`): the music's loudness (readings clearly above the tape noise, slowly averaged) is brought to -20 dBFS RMS, from -6 to +10 dB, at most +3 dB until 8 s of music are heard; a limiter keeps a boosted song from distorting. The loudness is remembered per song, so the right volume applies from the first second next time.
- Fix one-sided sound (`createBalance`): when one channel is at least 18 dB below the other for 3 s of music, the louder channel plays in both ears; it switches back when both carry the music.
- Equaliser: ten octave bands (31, 62, 125, 250, 500 Hz, 1, 2, 4, 8, 16 kHz; peaking filters about one octave wide, Q 1.4, with a low shelf at 45 Hz and a high shelf at 11 kHz for the outer bands so they are heard), ±12 dB in 1 dB steps. Presets: Flat, Bass boost, Clear voice, Old tape, Warm, Bright, Loudness, Small speakers, Choir and hall; moving a band makes it Custom. Headroom: the whole signal is lowered by 70 % of the largest boost before the bands, and the limiter (threshold -1.5 dB, ratio 20 without even volume; -10 dB, ratio 6 with it) catches what remains, so boosts never clip. With the two lowest bands boosted more than 2 dB, Clean up's rumble cut moves down to 45 Hz so a bass boost is heard; the panel notes that cassettes hold little below 60 Hz. Settings from the earlier three-band equaliser are carried over as Custom.
- Settings are kept per device (`zaideih.sound`); the Sound panel in Now playing (`src/ui/sound-panel.js`, tabs Clean up and Equaliser) shows them and what they did for the current song ("Skipped 7 s of silence at the start", "One-sided recording (left only)", "Volume evened out by +3 dB").
- The worklet is built as its own file (`assets/sound-worklet.<hash>.js`, `tools/build.mjs`) and loaded before the element is moved into the graph. Without it (an old browser) the filters and equaliser still work, and the panel names what is off.
- Test hook: a page that sets `globalThis.__soundTrace = []` gets every meter reading and decision.

## Audio

Every track streams from `https://media.zaideih.com/audio/{id}` (override with `ZAIDEIH_AUDIO_URL` at build time). The Worker looks the id up in D1 (`tracks`: `id`, `folder_path`, `mp3`) and serves `music/{folder_path}/{mp3}` from R2 with Range support.

The D1 table is loaded from `media.json`:

```bash
node tools/media.mjs d1 --apply            # writes build/d1/tracks.sql (idempotent upserts)
npx wrangler d1 execute audio --remote --file build/d1/tracks.sql --config worker/media/wrangler.toml
```

`--prune` additionally deletes D1 rows for tracks no longer in `media.json`.

Access rules in the Worker:

- `<audio>` requests (`Sec-Fetch-Dest: audio`) are served to any page, as before.
- `fetch()` requests (`Sec-Fetch-Dest: empty`), which the app uses to download songs for offline play, are served only to origins in `ALLOWED_ORIGINS`, with CORS headers. The desktop app's origin is `app://zaideih`.
- Fetch metadata headers deter casual hotlinking; they are not access control, since non-browser clients can send any headers.

## Playback diagnostics

A stream that fails with a network or "not supported" error is first retried once with a one-off `?fresh=` query, which skips the browser's saved copy: a copy saved from an older server answer (without the CORS header the CORS-mode player needs) is refused by the browser, and Chrome keeps range responses for a day. `#/help` explains the remaining cases to listeners.

When a song still fails, the player shows its message at once, then probes the failure (`src/core/probe.js`): for a downloaded song it reads the first 16 bytes of the saved file; for a stream it makes a ranged, uncached request for the first 16 bytes and reads the status and the Worker's `X-Zaideih-Meta` and `X-Zaideih-Reason` headers. The findings are packed into a diagnostic code (`src/core/diagnostic.js`): format version, what failed, flags (download, desktop, online, probed, unreachable, no D1 row, no R2 object), HTTP status, the file's leading-byte format, the Worker's lookup source, track id, size, app version and time, then a CRC-8, in Crockford base32 groups ("ZE-0420-R068-…"). The code holds no paths or personal data. It appears under the error notice and in Now playing, with a Copy button.

`tools/diagnose.mjs <code>` decodes it, names the likely cause and prints the track's R2 key with its code points and the D1 and R2 commands that check it; `track <id> --probe` does the same without a code. The app decodes codes on an unlinked page, `#/code/<code>`. A mistyped code fails the check digit and is refused with that reason.

## Usage statistics

Google Analytics 4 (`G-65TTKMZEGC`, set at build time as `ZAIDEIH_GA_ID`; empty disables) is built into production web builds only, never dev or desktop builds. `src/core/analytics.js` loads nothing until the listener chooses Allow on the first-visit card (basic consent mode); the choice is kept per device in `localStorage` (`zaideih.analytics`) and changed on the About page. While statistics are off (and the first-visit card is not showing), a "Share listening statistics" button sits at the foot of the sidebar and of the logo menu; it turns them on and disappears. Page views are sent by the app on each route change (`send_page_view: false`, since routing is by hash), with the address stripped of its query so search text is never sent, and a diagnostic code page reported as `#/code`. A `play_track` event (track, album and language ids) is sent once per song started. The CSP adds Google's documented hosts (`*.googletagmanager.com` for scripts; `*.google-analytics.com`, `*.analytics.google.com` and `*.googletagmanager.com` for images and connections) only when analytics is built in.

## Play counts

`src/core/plays.js` counts a play after 10 seconds of listening, measured from playback progress (seeking forward does not count; pause and resume count once), or near the end of a song shorter than that. Loading another song, a song ending and a restart from the beginning each start a new play. Plays wait in `localStorage` (`zaideih.plays`, newest 500 kept, a warning when older ones are dropped) and are posted to the audio Worker's `POST /plays` in batches of up to 50, 3 seconds after a play, when the device comes back online, and with `keepalive` when the page is hidden. The body is sent as `text/plain` so the request needs no CORS preflight. Counting is independent of the Google Analytics choice because nothing identifying is sent or stored: the track id and the time only; the Terms page says so. Builds set the address with `ZAIDEIH_PLAYS_URL` (default `/plays` on the audio origin; off in `--dev` builds), and the Worker counts only origins in `PLAY_ORIGINS`, so local testing never counts. Storage, limits and queries: [worker-audio.md](worker-audio.md#play-counts).

The counts come back with `GET /plays` on the same Worker (`src/core/playcounts.js`): totals per track and for the last 30 days, cached 5 minutes. Each track's count becomes its catalog count (`base`, from `albums.json`) plus its total, and album and artist totals, the most played lists and the languages' top artists are recomputed (`recount` in `src/core/catalog.js`), along with the artwork that shows popularity. The last answer is kept per device (`zaideih.playtotals`) and applied at start, so counts are there offline; fresh ones are asked for at start and on returning to the app, at most every 10 minutes, and pages that show counts redraw when they arrive. A failed request keeps the last counts.

## Offline

| What | Web | Desktop |
|------|-----|---------|
| App shell | Precached by the service worker | Bundled in the app |
| Catalog | Precached at install; `meta.json` network-first, catalog file cache-first | Bundled in the app |
| Downloaded songs | IndexedDB Blobs, played through object URLs | Same |
| Likes, playlists, history, queue | IndexedDB | Same |

Downloads use IndexedDB Blobs rather than Cache Storage because `<audio>` sends Range requests, which a service worker would have to answer with hand-built partial responses; Blobs avoid that and behave the same in Safari, Chromium and Electron. The app asks for persistent storage on the first download. The library can be exported to and restored from a JSON file. Signed in, liked songs and playlists sync across devices ([sync.md](sync.md)); history and downloads stay on the device.

## Desktop

`platforms/desktop/main.js` serves the built renderer over a privileged `app://zaideih` scheme, which gives the page a real origin for IndexedDB, Media Session (hardware media keys) and CORS. The window runs sandboxed with context isolation and no Node integration, refuses every permission request, blocks navigation away from the app, and opens web links in the default browser. The Content-Security-Policy allows media and fetch only from the app and the audio origin recorded in `app/build.json`. Electron is a dependency of `platforms/desktop` only, so web builds never install it.

## Versions

Releases use `yy.mm.dd.changes` (`v26.10.19.1`), stored without the `v` in both `package.json` files and bumped by `tools/version.mjs` (dry run by default). The build refuses an invalid version. The app shows the release version; the service worker cache is named by release plus a content hash of the build, so every build installs a fresh cache. The scheme is not semver: `npm version` cannot bump it, and installer tooling that requires semver (desktop packaging) will need it mapped, e.g. to `26.10.19-1`.

## Local development

`tools/dev.mjs` builds with `--dev` (unminified, source maps, no service worker), serves `dist/web` through `tools/serve.mjs` on `localhost:8080` and reloads the page after rebuilding. `tools/serve.mjs` applies `dist/web/_headers` like Cloudflare and answers Range requests; `npm run preview` uses it for the production build.

## Deployment

- Web: Workers static assets (`wrangler.jsonc`, Worker `zaideih`, files from `dist/web`, no Worker code). `dist/web/_headers` sets the CSP and caching: hashed assets and catalog files are immutable; `index.html`, `sw.js` and `meta.json` always revalidate. `index.html` carries the release in `<meta name="application-name" data-version>`, which the release workflow reads back from the live site.
- Releases: a push to master whose first line is `release: web|audio|d1|…` tests, builds and deploys with wrangler, then tags the commit and publishes the CHANGELOG.md section as a GitHub release: [releasing.md](releasing.md).
- Audio Worker: `npx wrangler deploy --config worker/media/wrangler.toml`. Step-by-step guide, including what changed when Django was removed: [worker-audio.md](worker-audio.md).
- CI (`.github/workflows/ci.yml`) runs the tests, checks the versions and `media.json` coverage, and builds both platforms on every push and pull request; the release workflow calls it as its gate.
